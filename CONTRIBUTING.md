# Contributing to Cross

Thank you for your interest in contributing to this project! We appreciate your time and effort in helping us build something great together.

## Community

- **Slack Community:** Coming Soon!
- **Weekly Meetings:** Coming Soon!

We hold weekly meetings to discuss ongoing work, review proposals, and connect with contributors. Everyone is welcome!

## Who We're Looking For

We welcome contributions from:
- **Developers**  
- **Designers** (UI/UX, graphics)
- **Documentation writers**
- **Testers and QA enthusiasts**
- **Anyone with innovative ideas** to improve the user experience

Whether you're fixing a typo or proposing a major feature, all contributions are valued!

## Contributor Responsibilities

When contributing to this project, please:

- **Ensure cross-platform compatibility** for Android and iOS on all changes
- **Create an issue first** before starting work on changes or enhancements
- **Discuss transparently** by engaging with the community and maintainers in your issue
- **Wait for approval** from a maintainer before beginning implementation
- **Be welcoming and respectful** to all community members, regardless of experience level or background

## How to Contribute

### 1. Create an Issue

Before writing any code, open an issue to discuss your proposed change:

- **Design changes:** Open an issue in the [Cross Design board]
- **Code changes/features:** Open an issue in the [Feature Releases board]

Clearly describe:
- What problem you're solving
- Your proposed solution
- Any alternative approaches you considered

### 2. Get Approval

- Your issue will be discussed at our next weekly meeting
- A maintainer will review and approve (or provide feedback on) your proposal
- This ensures your work aligns with project goals and prevents duplicate efforts

### 3. Fork and Clone

Once approved:

```bash
# Fork the repository on GitHub, then clone your fork
git clone https://github.com/ThriveEngineer/Cross.git

# Add the upstream repository
```

### 4. Create a Branch

```bash
git checkout -b feature/your-feature-name
```

Use descriptive branch names like `feature/add-dark-mode` or `fix/login-crash`.

### 5. Make Your Changes

- Write clean, readable code
- Follow existing code style and conventions
- Add tests if applicable
- Update documentation as needed

### 6. Commit Your Changes

```bash
git add .
git commit -m "Brief description of your changes"
```

Write clear, concise commit messages that explain what and why, not just what.

### 7. Push and Create a Pull Request

```bash
git push origin feature/your-feature-name
```

Then create a Pull Request (PR) to the `main` branch:

- Reference the original issue in your PR description (e.g., "Closes #123")
- Describe what you changed and why
- Include screenshots or videos for UI changes
- Ensure all tests pass

### 8. Code Review

- A maintainer will review your PR
- Address any requested changes
- Once approved, your PR will be merged!

## Questions?

If you have questions or need help:
- Ask in the Slack community
- Comment on your issue or PR
- Reach out during our weekly meetings

Thank you for contributing! 🎉
